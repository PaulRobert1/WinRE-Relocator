WinRE Relocator 3.0.1 - validation record
Date: 2026-11-19

Release scope
-------------
This patch fixes file operations through Windows volume-GUID paths.
No production disk operation or WinRE recovery boot was performed.
Tests execute extracted production helpers, disposable filesystem fixtures,
and simulated storage/native-command interactions. They do not execute the
main relocation workflow or call real DiskPart/REAgentC/BitLocker operations.

Defect and regression evidence
-------------------------------
The reported v3.0.0 failure was Get-Item rejecting a recovery image path
during preflight ("Illegal characters in path"). Inspection confirmed that
the same raw volume-GUID root was used for metadata, enumeration, hashing,
copying, and final verification.

The original v3.0.0 GUID manifest succeeded on this modern Windows runner:
https://github.com/PaulRobert1/WinRE-Relocator/actions/runs/44550927264
Therefore the original exception was NOT reproduced on that runner, and
this record does not claim all Windows PowerShell 5.1 hosts reject GUID
paths. The regression checks exercise the replacement native file adapter
directly so those operations no longer depend on provider normalization of
these paths.

The new suite was observed failing before the adapter was implemented
because its seven production helper functions did not yet exist. This is
a test-first implementation check, not reproduction of the user's exception.

The first full Windows run of the patch exposed an existing test-harness
difference in ConvertFrom-Json pipeline-array enumeration on PowerShell 5.1.
The test now assigns ConvertFrom-Json directly and retains the exact count
and argument-content assertions. No production native-command wrapper was
changed to make that test pass. The final Windows run above passed it.

Reproduce the checks
---------------------
From a repository checkout or the extracted release ZIP:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\qa\Run-Tests.ps1

On Linux:

  pwsh -NoProfile -File ./qa/Run-Tests.ps1

The Windows GUID suite creates a unique temporary directory on an existing
local volume and obtains that volume's existing GUID path with Get-Volume.
It neither assigns a drive letter nor changes partitions. It removes its
own temporary fixture in finally. An EFS or symbolic-link case is reported
as skipped if the host cannot create the corresponding fixture.

Production validation still required
--------------------------------------
These results do not establish Windows storage integration or WinRE bootability.
Before use on a critical server, validate the complete operation on a disposable
clone with a recoverable system/VM backup. In particular, test replacement
partition creation/type/attributes, C: extension, REAgentC staging/registration,
BitLocker suspend/resume where applicable, failures at the destructive boundary,
and an actual WinRE boot during a later maintenance window.

The patch adds native FILE access only. It does not establish that native
REAgentC accepts every GUID-path rollback registration on every Windows build.
The original rollback command's registration-path behavior is unchanged.
